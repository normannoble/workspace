Security Update: AI Agent Tools

Internal Security Communication

Context

We're choosing to be permissive and move fast with AI tool adoption. That's the right posture for Mindvalley—we don't want to gate everything and miss opportunities.

A New Category of Tool

We're adopting a new category of tool: AI agents that take autonomous actions on our behalf—installing software, executing code, accessing systems.

This is fundamentally different from traditional software where a human approves every action. Tools like Claude Code and open source frameworks like OpenClaw can do things the user didn't fully understand they authorized.

The Accountability Shift

With traditional enterprise software, vendors hold responsibility for security. If something goes wrong, there's accountability.

We have invested significantly in this space. We have a dedicated security team, industry-standard tooling, established processes for vendor reviews, access controls, and incident response, and we leverage Google's SOC for monitoring and protection. This foundation keeps us and our customers safe.

AI agents represent a new category—and our existing investment doesn't yet fully cover the specific risks they introduce. This new category works differently:

  • Commercial vendors like Anthropic hold limited liability for what their tools do
  • Open source tools hold zero accountability—it's explicit in the license
  • If something goes wrong, it's entirely on us

Risks We Are Accepting

By choosing to move fast and stay permissive, we are consciously accepting the following risks:

User-related risks

  • Unauthorized actions — Tools may install software, execute code, or make changes the user didn't fully intend to authorize
  • Data exposure — AI agents may access or transmit sensitive data without the user realizing
  • Understanding gap — People may not fully grasp what they're authorizing these tools to do

External risks

  • Attack vector — Bad actors may exploit AI agents as an entry point into our systems
  • Prompt injection — Malicious content in files, emails, or web pages could hijack an AI agent into taking unintended actions
  • Compromised dependencies — AI tools may install software or packages that contain malicious code

Accountability risks

  • No recourse — If something goes wrong, we cannot hold vendors accountable
  • Visibility gap — Until monitoring is in place, we are operating without full awareness of what's happening

We accept these risks because the alternative—gating everything and moving slowly—doesn't match Mindvalley's culture or competitive position. The response is not to restrict, but to build detection and response capability that matches the risk we're taking.

Where We Are Now

We don't currently have full visibility into what these tools are doing or where our exposure is. That's the gap I'm closing.

What I'm Doing

Building the safety net that lets us stay permissive while catching problems fast:

  • Monitoring & alerting — Improving visibility into AI tool activity and security events
  • Training — AI safe use training at onboarding and as a yearly refresher
  • Contracts — Working with HR on an AI safe use addendum to employment contracts
  • Incident process — Security issues trigger proper incidents with alerting, root cause analysis, monthly review, and exec reporting
  • Transparency — Sharing security status at A-Report

What This Means For You

No decisions needed. This is awareness.

You may hear about security incidents more often going forward. That's the system working, not things getting worse.
