Development Timeline

From initial concept to working prototype - the complete journey of building an AI-powered autonomous trash can

September
1st September

The Idea Takes Shape

I've been considering a concept for a trash can that automatically catches trash. I'm still deciding whether it'll catch trash mid-air or if the bin will move toward you to drop trash in it. I've been looking at motors on Shopee and Lazada to see what they have, and I've also been checking out various AI models to see which can identify objects. I will need to determine whether existing AI can track flying trash or if I'll need to train my own.

Research
2nd September

Design Decision

I've settled on the design where the bin finds the trash in my hand and rolls toward me. Once the trash is deposited, it will return to its original resting place (e.g., under my desk). I have selected the hardware as well. It will have two motorized wheels, two caster wheels, an Arduino, and an L298N motor driver. I intend to use a 9V battery for power with a switch. To make it look nice, I'll add a false bottom to conceal the electronics and wires.

Milestone Hardware
3rd September

Planning & AI Research

After checking and confirming compatibility, I drew a sketch and then emailed Mr. Steven to see if he would oversee me. I was also looking at AI models throughout the day for object tracking, such as YOLOv8. I'm still trying to figure out how to deploy and run the model on the bin so that it can track the trash in my hand and follow it around.

Research Software
4th September

Parts Ordered

Since Mr. Steven was okay with being my project supervisor, I spent the day creating a list of all the required items in a Google Sheet. I ordered the parts on Shopee and spent the rest of my day learning about the various AI models on Hugging Face.

Hardware Research
October
1st October

Parts Arrive - Testing Begins

Last few pieces showed up, the Arduino from Europe included, and it was go time. I taped the wheels down to my desk and plugged the Arduino into my computer for some testing. I wrote a quick script to drive each wheel forward and backward - so we know the motor functionality is working at least!

Milestone Hardware
3rd October

Speed Control & Keyboard Input

After I verified the motors, I began to play with speed by varying values between 1 and 255. I also figured out how to send keyboard input through the Serial Monitor, where 'W', 'A', 'S', and 'D' commands would move the bin and 'X' would stop it. My next step is to develop Python code that accommodates continuous input, so it streams the command to the terminal if a key is held down, allowing the bin to continuously move in a direction until the key is released or a different command is given.

Software Hardware
4th - 11th October

Continuous Motion Script

The development of this script for continuous motion was more challenging than I originally thought it would be. I had no idea that keeping the Serial Monitor open would interfere with Visual Studio Code's ability to connect to the Arduino. But after further research and learning about how to properly manage these ports and the USB connection, I got the control script working. This allowed me to control and move the wheels easier from my keyboard without having to hit enter for every single action or having to press the "x" key to stop. Then, I connected a joystick to my computer via Bluetooth and had keybinds for even smoother control.

Software Milestone
12th October

Autonomy Roadmap

I spent today determining the exact steps to make the bin fully autonomous. There are technical steps next, so I created a checklist for myself so I don't get confused:

  • AI Implementation: Find or train a model and plug it into VS Code. Run a Python script to pull the data for detection.
  • Movement Logic: Build the movement logic of the moving under me scenario - how far it needs to go, for how long, and how it comes back when it's done under the desk.
  • Bin: Build the bin with a false bottom for the L298N, Arduino, and battery, so it's hidden and protected. Drill a hole to tether the bin so it has a range.
  • Code Finalization: Integrate the code with all of this so that once trash is detected, everything is triggered.
Research
13th October - 1st November

Deep Learning Period

As a result of the difficulties with the script, I committed myself for the remainder of the month to develop a deeper understanding of electronics, Arduino, and Python integration. While this was a significant time commitment to research, I felt it was necessary to invest this time to potentially save myself additional time later during the project's final assembly and logic, and to leave extra room for troubleshooting or final improvements.

Research
November
2nd - 5th November

Decision to Build Custom AI

While researching in October, I came across thousands of AI models that already exist for trash detection. I sifted through them for three days to find one that would work for my purposes, but ultimately was unsuccessful, as the detection was either not accurate enough or not the objects I was targeting.

Yet it was through this research that I had an epiphany and realized that I could construct and train my own model. It is not difficult to do; it just takes a lot of work and time - but I knew this would be the solution to get the bin functioning the way I wanted it to.

Milestone Software
5th November - 19th December

Training the Custom Model

Building the custom AI model took much longer than expected. I had to collect and manually label around 1,000 photos for each object the bin needed to recognize to train the model. This was extremely tedious, and it took around seven hours of manual labor for each new object to be appropriately labeled. I had to pause for a few days as I was on holiday from the 13th to the 17th, but I have completed the primary data set.

Software
January
1st - 5th January

Physical Prototype Complete

I finished building the first physical prototype of the bin by adding the motors and the false bottom. I drilled all the electronic components into the false bottom and soldered multiple jumpers to provide reach to the motors. After the physical build, I corrected some balance issues to allow the bin to roll. With the hardware complete, I was able to run basic code that rolls the wheels for a few seconds at a time, indicating the mechanical prototype works.

Milestone Hardware
6th - 11th January

Balance Tuning & Command Memory

For the next five days, I was correcting balance problems and working through bugs in my script for the bin in Python. I balanced out the hardware specifically for the right and left motor, as the right motor was stronger, which made the bin veer off to the side. I balanced this out so it would drive straight. I also added a 50 ms memory of commands in the script; this way, if the AI tracking dropped out for even a split second, the bin would have some momentum instead of erratically stopping.

Software Hardware
12th - 24th January

Full Integration Complete

I spent the next 12 days working on changing my AI detection software and some of the files to better integrate with the movement system. I refined the tracking logic so the bin could smoothly follow the detected trash position from my webcam feed. I also implemented the return-to-home feature, where the bin remembers its starting position and rolls back after the trash is deposited. By the end of this period, I had a fully functional prototype that could detect trash in my hand, drive toward me, wait for the drop, and return to its resting spot under my desk.
